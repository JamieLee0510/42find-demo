# 用管道判成败，会得到假的绿灯

## 为什么

2026-09-06 跑三道闸门时写了 `cargo fmt --all -- --check 2>&1 | tail -20 && echo "✓ fmt"`。
`tail` 永远成功，所以 `&&` 后面那句必然打印——**报了绿，实际是红**，fmt 的差异就在上面几行摊着，
但那句「✓」比差异更显眼，差点就带着未格式化的代码往下走了。

同一类的还有：`npm install` 只花 1 秒就说 `changed 2 packages`，而那个包有 180 MB——
**退出码 0 不等于事情办成了**。同一天 `codex --version` 无输出但 `rc=0`，也是这个形状。

这不是 shell 的坑，是**判据放错了位置**：我判的是「最后一个命令成不成」，
要判的是「那件事成没成」。CLAUDE.md 第三节写着「能用规则判的绝不留给人判」——
规则判错了，比不判更糟，因为它带着权威。

## 怎么用

- **判成败的命令不接管道。** 要看输出就分两步：先跑并单独 `echo "rc=$?"`，再看输出。
  ```bash
  cargo fmt --all -- --check; echo "rc=$?"     # ✅ 拿到的是 fmt 的
  cargo fmt --all -- --check | tail -20 && ✓   # ❌ 拿到的是 tail 的
  ```
- 非要用管道，加 `set -o pipefail`（脚本里）或显式查 `${PIPESTATUS[0]}`。
- **装完必验产物，不信安装器的退出码**：核体积、核版本号有没有输出、核关键文件在不在。
  一个 180 MB 的包 1 秒装完，就是没装。
- 本项目的三道闸门（`fmt` / `clippy` / `test`）尤其适用——它们是「规则验证」那一层，
  假绿灯会一路放行到交付。
