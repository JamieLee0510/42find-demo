# exp001 · rg 在中日韩文本上的基准线

## 假设

`.42cog/intent.md` 的「不做什么」里写着「无索引的纯正则全盘扫描不做——ripgrep 已经把这件事做到头了」。
这句话当时是**推断，不是实测**。同时人写的定位是「中文友好…簡體繁體、半角全角、詞在句中的匹配」。

**待验假设**：rg 在这三件事上确实失手，因而 42find 有存在的空间。

## 做法

- 工具：`ripgrep 15.2.0`（`cargo install ripgrep`，`~/.cargo/bin/rg`）
  ⚠️ **不能用 shell 里那个 `rg`**——Claude Code 注入了一个同名 shell 函数，转给 `claude` 内置的 14.1.1。
  测基准必须走 `~/.cargo/bin/rg` 这个真二进制。
- 语料：`corpus/` 四份小文件（简体 / 繁体 / 全半角混排 / 词在句中），人工可数，命中数可以逐条核对。
- 每个查询记「命中几处、落在哪些文件」。

## 结论

| 查询 | 命中 | 落在 | 判读 |
|---|---|---|---|
| `检索`（简） | 3 | `a-simplified` `d-inline` | 只找简体 |
| `檢索`（繁） | 1 | `b-traditional` | 只找繁体 |
| `index_path`（半角） | 1 | `c-fullwidth` 的半角那行 | 只找半角 |
| `ｉｎｄｅｘ＿ｐａｔｈ`（全角） | 1 | `c-fullwidth` 的全角那行 | 只找全角 |

**一、簡繁不互查——坐实了。** 查简体查不到繁体那份，反之亦然。这是 42find 最硬的存在理由：
同一个概念的两种写法，rg 当成两个毫不相干的字符串。

**二、全半角不归一——坐实了。** 同一个文件里的两行，半角查询只命中半角那行，全角只命中全角那行。
`rg -o` 逐段核过，不是行级巧合。

**三、「詞在句中的匹配」不是 rg 的短板——假设在这一条上被推翻。**
`检索` 在 `d-inline.txt` 里夹在句子中间、无空格分隔，rg 照样命中 2 处。
原因：rg 做的是**子串匹配**，根本不分词，所以没有切错的机会。

> **这一条要回写进意向书。** 「词在句中」是**索引类工具**的难题（42find 用索引就必须自己解决它），
> 但它**不是相对 rg 的优势点**——拿它当卖点会落空。
> 42find 真正能赢 rg 的是前两条：字符层面的归一（簡繁、全半角）。
> 也就是说：意向书「真难题」第 2 条（切分）是**上索引之后自己给自己挖的坑**；
> 而字符归一**不是难题、是收敛方向的本体**——它是用户实际感受到的痛，基础映射就是查表，
> 难的只有一对多与异体字那截尾巴。（已按此回写 `.42cog/intent.md`，2026-09-06。）

## 边界

- **规模边界**：语料只有 4 份小文件、十几行，只证明「rg 的行为是这样」，**不证明任何性能结论**。延迟要等 `hyperfine` 和真实语料。
- **时间边界**：rg 15.2.0（2026-09 实测）。rg 若哪天加了 Unicode 归一化选项，第二条结论作废。
- **未测**：异体字（户/戶/户）、日文假名、繁简一对多（发/發·髮），这三类是黄金查询集必须补的坑。
